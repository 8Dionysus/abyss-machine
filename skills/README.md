# abyss-machine Skill Home

This directory is the canonical source home for callable procedures owned by
`abyss-machine`. It is not a mirror of the shared AoA catalog or the globally
installed Codex directory.

## Admitted bundle

| Bundle | Capability | Visibility |
| --- | --- | --- |
| `os-abyss-artifact-trust-loop` | Route one artifact through owner controls, evidence, registry selection, and exact consumer admission | OS-user-advertised |

The bundle preserves one coherent trigger and contract across inspection,
owner-routed preparation, admission, and audit. Those phases remain internal
until held-out work proves that separate prompt-visible procedures improve
selection, composition, and outcomes.

## Admission

Manual owner trials established a real procedural gap between raw artifact
commands and a safe consumer decision:

- a public-source artifact was built, verified, promoted in an isolated
  registry, and admitted for an agent consumer;
- an empty registry remained `unknown`, a mismatched source ref was denied, and
  a production consumer using local-only trust required manual review;
- a degraded or identity-incomplete MCP observation required source-CLI
  fallback rather than being flattened into a green result;
- unrelated source edits and generic security questions remained outside the
  trigger.

Only these durable conclusions live here. Trial prompts, traces, temporary
bundles, registries, rubrics, and task-local DAGs remain session-local and are
removed after use.

`port.manifest.json` declares the canonical package and its selection by the
single OS-level `os-user-default` profile. This repository does not duplicate
the bundle under `.agents/skills`.

## Verification posture

Manual tasks establish usefulness. `skills/AGENTS.md` defines the boundary.
Portable shape, owner-home integration, generated contracts, and repository
release lanes are supporting checks only; none can prove routing quality or
consumer safety by itself.
